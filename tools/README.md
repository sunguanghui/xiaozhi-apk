# 小智盒子控制工具 · 使用说明

这是一个**可独立使用的工具目录**：整个 `tools` 文件夹拷贝到任意电脑、任意路径都能用，不依赖 Android 源码工程。

> 想用浏览器查看这份说明：双击同目录下的 `README.html`（离线可用，自动适配深浅色）。

## 一、目录内容

| 文件 | 作用 |
| --- | --- |
| `xiaozhi-device.bat` | 双击打开菜单；也可在命令行带参数调用 |
| `xiaozhi-device.ps1` | 主脚本（Windows 自带 PowerShell 5.1 即可） |
| `app-debug.apk` | 要安装到盒子的应用，**与脚本放在同一目录**；文件名不限，见下方说明 |
| `platform-tools\`（可选） | 已随目录附带 `adb.exe` 及其 DLL，无需另外安装 Android SDK；也可以直接把 `adb.exe` 放在本目录 |
| `README.html` | 同一份说明的网页版，双击用浏览器打开 |
| `.gitignore` | 排除 `*.apk` 与 `platform-tools`，避免构建产物和第三方二进制进版本库 |

脚本查找 adb 的顺序：`本目录\adb.exe` → `本目录\platform-tools\adb.exe` → 环境变量 `ADB` → 本机 Android SDK → `PATH`。

脚本查找 APK 的规则：`-Apk` 参数指定 → 本目录的 `app-debug.apk` → 本目录里**唯一**的 `.apk`（叫什么都行，比如 `R1Xiaozhi.apk`）。目录里有多个 `.apk` 时必须用 `-Apk` 指定，避免装错文件。

## 二、准备工作

1. 盒子与电脑连在**同一局域网**，盒子已开启 ADB 调试（本设备监听 `5555` 端口）。
2. 记住盒子的 IP（路由器后台或盒子设置里查看，例如 `192.168.1.20`）。
3. Windows 10/11 自带 PowerShell 即可，无需另外安装。

## 三、开始使用

**方式一：双击** `xiaozhi-device.bat`

先按提示填写盒子 IP，然后出现菜单，输入序号执行；执行完可按回车回到菜单继续操作，输入 `0` 退出。选 `1`（安装）时会先提示“会卸载旧版本并清除应用数据”，输入 `y` 确认后才开始。

```
请先填写盒子的 IP 地址（后续所有操作都在这台设备上执行）。
设备 IP（例如 192.168.1.20）: 192.168.1.20
==============================================
  小智盒子控制台
==============================================
   1. 安装应用            install（装完自动打开）
   2. 打开应用            start   （自动连接 + 开始对话）
   3. 退出应用            stop    （释放麦克风）
   4. 开机自启：开启      boot-on
   5. 开机自启：关闭      boot-off
   6. 查看状态            status
   7. 卸载应用            uninstall
   0. 退出
```

**方式二：命令行**（在本目录下执行）

```powershell
.\xiaozhi-device.bat start
.\xiaozhi-device.bat status -Device 192.168.1.20
```

每次运行都会先要求填写盒子 IP：

```
请先填写盒子的 IP 地址（后续所有操作都在这台设备上执行）。
设备 IP（例如 192.168.1.20）: 192.168.1.20
```

- 只填 IP 会自动补上 `:5555` 端口；也可以直接填 `192.168.1.20:5555`
- 不填直接回车会取消本次操作，不会对设备做任何事
- 加 `-Device` 参数可跳过输入

首次连接时盒子会弹出“允许 USB 调试”之类的授权框，同意一次即可。

## 四、命令说明

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `menu` | 交互菜单（默认） | 不带参数运行脚本时进入；双击 `.bat` 即为此模式 |
| `install` | 安装并打开应用 | **先检查设备上是否已安装，已安装则先卸载再安装**。卸载会清除应用数据（设置恢复默认），但绑定信息保存在服务端、按设备识别，**重装后无需重新绑定**；应用在运行时会先正常退出；APK 文件名不限；**安装成功后自动打开应用**（自动连接、进入语音对话） |
| `start` | 打开应用 | 自动连接服务器、自动开始语音对话、占用麦克风；会先停掉厂商语音助手以释放麦克风 |
| `stop` | 退出应用 | 断开连接、释放麦克风、结束进程；**不修改开机自启设置** |
| `boot-on` | 开启开机自启 | 盒子重启后自动打开应用 |
| `boot-off` | 关闭开机自启 | 盒子重启后不会自动打开应用 |
| `status` | 查看状态 | 应用是否在运行、界面是否打开、开机自启状态、厂商助手是否在运行、最近日志 |
| `uninstall` | 卸载应用 | 先正常退出再卸载；**应用数据（设置、本地配置）会一起清除**，绑定信息在服务端，重新安装后仍然有效 |

可选参数：`-Device <IP[:端口]>`、`-Apk <APK路径>`、`-Adb <adb.exe路径>`。

**对话中语音退出**：和小智聊天时说出“**退出小智**”，应用会在助手回复播完后自动退出并释放麦克风（效果等同 `stop`）；服务端没有回复时最多等 8 秒。文字输入“退出小智”同样有效。

## 五、典型流程

**1. 首次部署到一台新盒子**

```powershell
.\xiaozhi-device.bat install
```

安装完成后会自动打开应用并连接，不需要再执行 `start`；没有绑定的设备会**语音播报 6 位绑定码**，到 [xiaozhi.me](https://xiaozhi.me) 输入该码完成绑定，之后每次 `start`（或 `install`）即可直接对话。

**2. 日常使用**

需要时 `start`，不需要时 `stop`——麦克风只在 `start` 期间被占用。

**3. 升级应用**

用新的 APK 替换目录里的旧文件（文件名可以不同，例如 `R1Xiaozhi-v1.0.1.apk`；目录里只留一个 `.apk` 时会自动用它），执行 `install`，装完会自动打开应用。

> `install` 会**先卸载旧版本**，应用数据（设置、本地配置）会一起清除，但**绑定信息保存在服务端、按设备识别，重装后无需重新绑定**，安装完成会自动打开并继续使用。注意设置项会恢复默认：开机自启默认关闭，需要的话重新执行 `boot-on`。

**4. 换一台盒子**

直接运行脚本，填写新盒子的 IP 即可。绑定信息跟随设备（不同盒子需要各自绑定）。

**5. 不再使用**

```powershell
.\xiaozhi-device.bat stop
.\xiaozhi-device.bat uninstall
```

## 六、两个“自动”开关的区别

应用设置页里有两个独立开关，脚本操作也对应分开：

| 开关 | 设置键 | 作用 | 由谁修改 |
| --- | --- | --- | --- |
| 应用启动后自动连接并开始对话 | `auto_start` | 应用被打开后是否自动连接、自动开麦 | `start` 会确保它打开；应用设置页 |
| 开机自动启动应用 | `boot_auto_start` | 盒子重启后是否自动打开应用 | `boot-on` / `boot-off`；应用设置页 |

开机自启**默认关闭**：新装或清除数据后，盒子重启不会自动打开应用，需要时用 `start` 拉起。`start` / `stop` 都**不会**修改“开机自启”；如果想让盒子每次开机就自动进入对话，执行 `boot-on`。

## 七、常见问题

**找不到 adb**
本目录已附带 `platform-tools\adb.exe`，正常不会出现这个问题。如果手动删除或替换过，注意 `adb.exe` 必须和 `AdbWinApi.dll`、`AdbWinUsbApi.dll` 放在一起；也可以用 `-Adb` 指定任意位置的 adb。

**设备未连接 / offline**
检查 IP 是否正确、盒子是否开机、电脑与盒子是否同网段；可先在命令行执行 `adb connect 192.168.1.20:5555` 再运行脚本。盒子重启后需要几秒网络才恢复。

**提示 APK 不存在 / 有多个 APK**
把 APK 放到脚本同目录（文件名不限，`app-debug.apk` 只是默认优先项），或用 `-Apk` 指定完整路径。目录里有多个 `.apk` 时脚本不会猜，必须用 `-Apk` 指定要安装的那一个。

**`start` 后没有反应 / 不说话**
先跑 `status` 看最近日志。常见原因：网络未就绪（应用会自动重试）、盒子还没绑定、厂商语音助手占着麦克风（脚本已自动 `force-stop` 它）。

**应用没在跑，但 `status` 显示“只有空闲进程”**
这是开机广播留下的空进程，不占麦克风，可以忽略。

**卸载重装后要重新绑定吗**
不需要。绑定关系保存在小智服务端并关联设备 ID，卸载只会清除应用本地数据；重装后 `start` 会直接连回原设备，仍可正常对话。只有换一台盒子（新的设备 ID）才需要重新绑定。

**不要用任务管理器强杀应用**
应用正在录音时强杀进程，可能让这台盒子的音频服务卡死，之后谁都无法使用麦克风，只能重启盒子恢复。退出请用 `stop`（`install` / `uninstall` 内部也是先正常退出再操作）。

**改了脚本后中文报错 / 无法解析**
`xiaozhi-device.ps1` 必须保存为 **UTF-8 带 BOM**，否则 PowerShell 5.1 会按 GBK 读取，中文注释会导致语法错误。

**重启后应用没有自动启动**
开机自启默认是关闭的，需要先执行 `boot-on`；另外新安装的应用在 Android 里处于“停止状态”，需要先 `start` 一次（或用过应用），开机广播才会送达。

## 八、安全说明

- 远程控制广播要求 `android.permission.DUMP` 权限，只有 adb shell、系统或特权应用能发送，普通应用无法控制本应用。
- 脚本只做局域网内 adb 控制，`status` 输出的日志已过滤掉 token、设备 ID 等敏感内容。
- 应用里保存的 WebSocket Token 已排除在云备份 / 设备迁移之外。
